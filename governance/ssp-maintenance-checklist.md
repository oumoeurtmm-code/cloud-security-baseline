# SSP Maintenance Checklist

This checklist supports ongoing updates to a System Security Plan (SSP) as the environment changes.

## What Is an SSP

A System Security Plan documents how a system implements required security controls. It is a living document — it needs to reflect the current state of the system, not just the state at initial authorization.

## Review Triggers

Any of these should initiate an SSP update:

- Architecture change
- New service deployment
- IAM or privileged access model change
- Logging or monitoring changes
- New external integration
- Major vulnerability or incident
- Policy or control update
- Personnel change in key security roles

## Checklist

- [ ] Update system description to reflect current architecture
- [ ] Update boundary and data flow diagrams
- [ ] Review inherited vs implemented controls
- [ ] Update control implementation statements
- [ ] Refresh roles and responsibilities section
- [ ] Update inventory of major system components
- [ ] Confirm logging and monitoring coverage is accurate
- [ ] Confirm incident response references are current
- [ ] Review evidence links and attachments
- [ ] Record revision date and approver

## Notes

An SSP that does not match the actual system creates compliance risk. Keep it current as the environment evolves, not just at assessment time.
